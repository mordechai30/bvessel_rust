# GPU authority and version boundaries

Use WebGPU contracts for portable host behavior and WGSL for shader semantics. Resolve Rust signatures,
features, and backend restrictions against the locked wgpu release; published language support does not
establish implementation support. Keep exact contract links beside the decisions in the topic references.

Treat retained Rust 30.0.1 spellings as examples. Recheck immediate data, staging belts, mapped access,
error scopes, surface outcomes, and descriptors when the locked version differs; do not upgrade to fit them.

Use inspected examples only for these mechanisms:

- Inspect [wgpu boids][boids] for compute-produced vertex data and encoded simulation/render dependencies.
- Inspect [wgpu uniform values][uniforms] for shader-aware serialization rather than inferring ABI from Rust
  field types.
- Treat learn-wgpu as parameter/layout teaching; reject manual Pod shortcuts unless the actual complete
  trait contract holds. Treat Bevy extraction, pipeline state, and transparent ordering as implementation
  evidence, not permission to impose its ECS or runtime.

Keep inspected commits distinct from the 30.0.1 API baseline:

- wgpu v30: a0bd44d7ffa87b6127fb37050af4b7db741718e2.
- learn-wgpu: d90b30088fceae214c53603207464c874a08b6d8.
- Bevy: c8d199b192a1b173746f7a160d259c4db8ab7789.

Do not claim exhaustive repository/link review or infer validity/performance from a showcase.
