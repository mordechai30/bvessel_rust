# Shader input selection and specialization

| Lifetime/access | Mechanism | Material cost or constraint |
| --- | --- | --- |
| Shader invariant | const | Source change rebuilds affected modules/pipelines |
| Structural variation | Deterministic generated source | Bound variants; retain source diagnostics |
| Pipeline-time scalar | override | Cache a bounded specialization set |
| Small runtime record | Uniform | Binding-size limits and actual record layout |
| Many command records | Dynamic uniform ranges | Padded allocation and offset/bind cost |
| Dense/GPU-produced table | Indexed storage | Indexing, access limits, and traffic |
| Tiny command-local values | Immediate data | Feature/byte limit and recorded state |
| Regular attributes | Vertex/instance stream | Fixed decoding versus manual pulling |
| Spatial/filtered access | Texture | Format, sampling, view, and mip semantics |

Use built-ins for execution-provided indices/IDs and stage outputs for actual interpolation. Match
locations/types/interpolation; use flat integer IDs. Compare large varying records with recomputation or
fragment lookups. A uniform cannot determine workgroup size; read-only runtime data is not a compile-time
constant.

## Overrides

- Use legal scalar override types and supply statically used overrides lacking defaults. For @id(n), use
  the decimal ID string in PipelineCompilationOptions::constants; otherwise use the identifier, never both.
- Set constants independently for each programmable stage; explicitly agree values where stages share them.
- Specialize stable algorithm/workgroup choices only when useful. Do not rebuild pipelines for each object,
  color, transform, time, or frame; generated source must keep bindings deterministic and locations traceable.
- Validate overridden workgroup size against axis/product limits and derive matching host dispatch counts.
- Keep WGSL in include_str files when convenient; a browser's string interpolation pattern is not a Rust rule.

## Runtime tables

- Start with uniforms for small CPU-written records. Use dynamic ranges when draws share a layout but
  need distinct records; use indexed storage when records exceed uniform limits, are GPU-produced, or
  measured padding/binding cost warrants it. Use instance streams for repeated geometry with regular
  per-instance attributes. Choose immediate data only for tiny command-local values on supported devices;
  retain a buffer path when portable targets lack that capability.
- Split common frame data, static records, and changing records when saved uploads justify the bindings.
- Reuse a stable binding after content updates. An indexed uniform table still obeys uniform array rules
  and binding-size limits. Batch repeated geometry with instances when that preserves required ordering.
- Permit compute output to feed a fixed vertex stream with STORAGE|VERTEX; compute access does not force
  pulling. Storage reads must explicitly reproduce packed/normalized vertex decoding when that path is selected.

## Rust 30 immediate data

- Check IMMEDIATES and max_immediate_size; request both required_features and a nonzero required limit.
- Set PipelineLayoutDescriptor::immediate_size; in 30.0.1 bind_group_layouts is a slice of optional layouts.
- Set command bytes with render/compute/bundle set_immediates, respecting four-byte offset/count granularity.
- Prefer small indices into persistent tables over copying large records. Initialize every accessible slot
  before a draw/dispatch, again after a pass starts or bundles execute; unused padding slots are exempt.
- Treat bundle-recorded immediate values as fixed; use referenced buffers or indirect data for changing
  values.
- For portable immediate WGSL, use at most one statically accessed variable per entry point and avoid arrays
  or structures containing arrays. Keep Rust 30 immediates free of f16 despite separate arithmetic support.
- For older releases, verify PUSH_CONSTANTS, max_push_constant_size, push_constant_ranges, stage setters,
  and var<push_constant> as native/version-specific APIs; do not mix them with the immediate-data descriptors.
