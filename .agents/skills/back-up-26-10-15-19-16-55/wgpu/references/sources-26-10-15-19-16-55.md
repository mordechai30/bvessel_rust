# GPU authority and version boundaries

Use published WebGPU for portable resource/command contracts and WGSL for shader rules. Use the exact
resolved wgpu release for Rust descriptors, flags, features, callbacks, and native restrictions. Published
language support alone does not prove Naga, browser, driver, or device implementation support.

The retained concrete spellings target wgpu 30.0.1. Check immediate data, staging belts, mapped access,
error scopes, surface acquisition/presentation, and descriptor fields before using another release.
Do not upgrade the project to fit examples or import browser/C++ signatures literally into Rust.

Use these inspected snapshots as optional evidence, not mandated dependencies or architecture:

- wgpu v30 commit a0bd44d7ffa87b6127fb37050af4b7db741718e2: queue/belt timing and lifetime, boids'
  compute-produced vertex stream, and uniform_values shader-aware serialization.
- learn-wgpu commit d90b30088fceae214c53603207464c874a08b6d8: useful parameter/layout examples;
  do not adopt manual-Pod shortcuts unless the complete actual trait contract holds.
- Bevy commit c8d199b192a1b173746f7a160d259c4db8ab7789: encoded uniforms, extraction ownership,
  pipeline/state management, and transparent ordering.

Keep those snapshots distinct from the 30.0.1 API baseline. Treat local specification snapshots,
tutorials, Fundamentals, official samples, LearnWebGPU, and GPUWeb's explainer as evidence with different
roles. Ideas/showcases do not establish performance or validity. Do not claim exhaustive repository/link
review or inherit unrelated source workflows, fixed thresholds, pure-core architecture, or frameworks.
