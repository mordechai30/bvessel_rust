# GPU diagnostics, verification, and measurement

## Contract and recovery evidence

- Compile host APIs against the resolved crate and validate selected WGSL entry points on actual backends.
- Check known host/shader offsets/values, serialized bytes, minimum/bound ranges, distinct draw parameters,
  nonzero dynamic offsets, partial final workgroups, multiple encoded steps, and inactive-lane barriers.
- Check delayed completion, bounded pool saturation, reordered CPU producers, and stale readbacks after
  resource replacement/device loss. Exercise zero-size resize, surface outcomes, and capability fallbacks.
- Label resources/passes/pipelines by purpose and variant, and retain locations for generated WGSL.
- Install uncaptured-error and device-loss reporting. Keep recoverable creation errors in narrow scopes;
  Rust 30 push_error_scope returns a guard, whose pop returns the future. Pop before await and nest in
  reverse creation order; do not span unrelated work or async task reordering.
- In Rust 30, on_uncaptured_error accepts Arc<dyn UncapturedErrorHandler>; device-loss callbacks are Send
  and static with reason/message. Verify exact signatures before adapting older/browser handlers.

## Measurement

- Measure CPU preparation, encoding, GPU execution, transfers, and frame/presentation latency separately.
  Keep workload, resolution, geometry, iteration count, and output quality comparable across target backends.
- Separate startup/pipeline warming from steady state and inspect frame distributions, not only averages.
- For portable pass timestamps, grant TIMESTAMP_QUERY; gate inside-pass/encoder timestamp features separately.
  Multiply Rust timestamp deltas by Queue::get_timestamp_period for nanoseconds.
- Resolve into QUERY_RESOLVE|COPY_SRC, then copy to MAP_READ|COPY_DST; align query resolve offsets to 256.
  Read asynchronously and reclaim completed query slots; reject stale, invalid, unavailable, or misleading
  zeros.
- Compare pass timings with whole-frame captures: indirect validation, copies, clearing, and backend work
  can sit outside pass timestamps. Use backend captures such as Xcode GPU capture on Metal when available.
- Test batching, bundles, pass fusion, dynamic uniforms, workgroup sizes, f16, and branch removal as
  hypotheses. A shader improvement is not necessarily a frame improvement; preserve numerical and visual quality.
- Report hardware/backend, granted features, compiler/crate, workload, repetitions, output checks, and limits.
  Do not claim GPU tests, soundness, portability, or benchmarks from host compilation or unexecuted examples.
