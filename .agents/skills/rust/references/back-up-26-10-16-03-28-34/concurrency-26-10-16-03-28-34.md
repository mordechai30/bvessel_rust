# Concurrency, suspension, and completion

## Execution and transfer

- Keep small work sequential and await directly when independent scheduling is unnecessary. Preserve the
  existing async runtime for nonblocking I/O and framework CPU pools for sustained parallel computation.
  Use scoped threads for finite borrowed work; use a dedicated service thread or supported local executor
  for persistent ownership/affinity. Preserve construction, use, and destruction on the required thread.
- Join I/O futures for concurrent polling, not CPU parallelism. Keep blocking/long CPU work off executor
  workers.
- Partition outputs and merge local reductions before shared writes; benchmark scheduling granularity and
  skew.
- Check the whole future's captured and suspended state for Send. Borrowing across await is legal when its
  lifetime and bounds fit; cloning Rc cannot make it Send, and async move does not extend a borrowed lifetime.
- Distinguish callable Send from its returned future's Send. Express public future bounds where callers
  need spawning; use erased boxed futures only when runtime heterogeneity requires them.
- Preserve local-task lifetime requirements for non-Send futures. A current-thread runtime does not remove
  ordinary Tokio spawn's Send/static bounds.
- Inspect large inline buffers/nested futures before boxing. Box a large inner future when measured task
  size justifies allocation/indirection; type erasure is a separate runtime-polymorphism decision.
- Check wrapper auto traits, ignoring additional allocator bounds:

  | Wrapper | Send requires | Sync requires |
  | --- | --- | --- |
  | &T | T: Sync | T: Sync |
  | &mut T, Box<T> | T: Send | T: Sync |
  | Arc<T> | T: Send + Sync | T: Send + Sync |
  | Mutex<T> | T: Send | T: Send |
  | RwLock<T> | T: Send | T: Send + Sync |
  | Cell<T>, RefCell<T> | T: Send | Unavailable |
  | Rc<T> | Unavailable | Unavailable |
  | Raw pointers, NonNull<T> | Not automatic | Not automatic |

- Prefer derived auto traits. Use a deliberate private marker such as PhantomData<Rc<()>> for stable
  thread-transfer exclusion when appropriate; a mutex cannot repair a foreign handle's thread affinity.

## Admission, guards, and state transitions

- Bound admission before spawning/capturing large inputs. Budget pending producers, queued closures,
  message bytes, active/blocking work, and retained completed results, not only channel items or workers.
- Carry admission permits for the complete resource lifetime; drain completions during sustained input.
- For required lossless work, wait for capacity within the request deadline or reject admission explicitly.
  Coalesce replaceable state to the latest value; do not silently drop required commands. Use broadcast only
  when receivers have a defined lag/recovery policy; use one-shot replies for one result.
- Avoid permit/lock cycles where a holder waits for work requiring the exhausted resource.
- End ordinary mutex/DashMap guards before suspension or reentrant callbacks. Permit async guards across
  await only for a deliberate operation; define lock order, reentry, cancellation, and fairness.
- Compare owner tasks with bounded commands when locking serializes unrelated requests.
- Validate a snapshot version under the commit lock before applying potentially stale computed results.
- Select RwLock from measured hold times, fairness, and writer latency, not read percentage alone.
  Do not keep a read guard while acquiring a write guard on the same lock; release and validate state
  again, or use an API whose documented upgrade operation meets the actual requirement.
- Treat poisoning as advisory; repair or validate state before recovering a poisoned guard.

## Cancellation and supervision

- Inspect operation-specific cancellation safety. select drops losing futures; retain partial I/O buffers
  and offsets outside those futures. read_exact and write_all can hide partial progress; use resumable
  incremental operations when cancellation must preserve it. Define incomplete EOF and trailing-data policy.
- For try_join, define cancellation of unfinished branch futures on the first error. If branches await
  spawned handles, preserve separate ownership of those tasks: dropping a handle detaches its task.
- Reserve send capacity before transferring a value when cancellation must preserve ownership.
  Repeated canceled lock/semaphore acquisition can lose queue position.
- Define idempotency, transactions, or reconciliation for retries; timeout does not undo external effects.
- Use result-bearing handles/JoinSet when task failures affect the caller. Use TaskTracker only when results
  are reported separately and shutdown needs lifetime tracking. Distinguish application errors from
  panic/cancellation. is_finished checks readiness without collecting a result. Borrow a handle into
  timeout; dropping an owned Tokio JoinHandle detaches its task. Keep a supervisor alive through cleanup.
- Join ordinary thread handles explicitly; dropping std::thread::JoinHandle detaches, whereas a scoped
  thread is joined by its scope. Keep worker-panic handling explicit.
- Stop admission, close every retained input sender, cancel/drain by policy, then observe termination and
  finish fallible flush/commit. Define what happens when a shutdown deadline expires.
- For JoinSet, abort_all requests cancellation; drain results to observe it. Dropping the set does not await.
  shutdown waits but discards results; drain explicitly when failures matter.
- Do not use TaskTracker::close as an admission barrier or its wait as a substitute for result inspection.
- Cooperatively stop started spawn_blocking closures; abort or runtime shutdown timeouts need not stop them.
  Use a process boundary when hard termination is required and cooperative termination cannot satisfy it.
- Define sibling failure policy and cleanup-error reporting; do not return early leaving silent background
  work.
- Test biased select for starvation; deliberate shutdown priority does not solve all fairness problems.

## Custom atomics, futures, and streams

- Prove publication and reclamation separately. Release/acquire synchronization requires observing the
  relevant release/sequence; SeqCst does not create a multi-field transaction or order every relaxed access.
- Use Relaxed for independent statistics only when no payload publication depends on it. Choose the weakest
  ordering from a written argument, not a hardware-reordering story.
- For compare_exchange, failure ordering is load-only, never Release/AcqRel; account for relaxed halves of
  Acquire/Release RMW operations, spurious weak failures, ABA, wraparound, and progress guarantees.
- Close check/register races in custom polling; update wakers when context changes and provide a wake path
  after Pending. Wake outside state locks where possible; bound per-poll work and arrange later progress.
- Preserve pin projection and post-completion polling contracts through state transitions.
- Bound stream concurrency and buffered outputs separately. Ordered adapters can retain later results
  behind a slow first item; unordered adapters change delivery order. Bound fold accumulators too.
- Test saturation, sender retention, worker panic, receiver closure, cancellation at partial progress,
  snapshot conflicts, and observed destruction. Measure queue bytes, permit wait, lock hold, and tail latency.
