# Project instructions

## Mandatory policy

- Prefer clear names, explicit validation, and straightforward control flow over brevity.
  Accept extra complexity only for a material requirement or measured benefit.
- Preserve edition, MSRV, toolchain pins, supported targets, runtime, dependency policy, and public contracts.
- Prefer suitable safe APIs. Permit necessary sound FFI or a justified narrow unsafe abstraction when
  safe alternatives materially complicate code or dependencies. Do not ban dependencies for internal unsafe.
- Ask when requirements or supplied references are materially unclear or unavailable.
- Present material source conflicts with exact advice and practical effects; pause the affected decision
  for resolution. Reuse explicit prior resolutions, including the existing necessary-FFI exception.
- Follow the user's current authorization boundaries; do not infer permission for installs or updates.
- Report missing assets and unrun or unsupported checks. Discard unrelated fetched material from working
  context.

## Task routing

- Use the `rust` skill for Rust contracts, implementation, migration, tooling, or CPU performance work.
- Use the `wgpu` skill for WebGPU through Rust wgpu/WGSL, including GPU design, data flow, and validation.
- For mixed work, select each skill's relevant references; do not load either collection in full.
- Keep verified repository-specific details in root `references/`; keep reusable guidance inside its skill.

## Project conventions

- Follow the Rust Style Guide and the project's rustfmt/style edition. Retain clearer control flow over
  shorter lint rewrites; keep justified allowances narrow.
- Use meaningful names for units, ownership, capacity, admission, and completion.
- Keep comment-only code lines within 80 characters excluding indentation, or the smaller project code width.
- Before committing new nontrivial code, document fields with at least one purpose line and functions/types
  with
  at least two lines covering purpose, usage, and material implementation details.
  Put useful contracts before item attributes.
- Use the usual four-space, 100-character Rust layout unless the project specifies another style.
- Preserve existing hooks; integrate applicable check-only formatting and lint checks without overwriting
  them.
