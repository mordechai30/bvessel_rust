# Material Rust/C++ translation

Use this reference only for actual migration or a language-contract question. Do not add language
comparisons to ordinary code changes. Preserve semantics rather than translating syntax or reproducing UB.

- Translate ownership transfer explicitly: Rust non-Copy moves invalidate source bindings without C++
  custom move constructors. C++ moved-from state remains type-specific; neither model promises a literal
  memcpy.
- Revalidate views after mutation/reallocation. C++ spans/string_views do not enforce owner lifetime or
  exclusivity; safe Rust borrows do. Invalidated C++ access is UB, not a guaranteed crash.
- Use take/replace only with a valid Rust replacement; moving from an ordinary borrowed field cannot leave
  it uninitialized. Check opposite member destruction order: Rust declaration order, C++ reverse order.
- Distinguish address stability from move deletion. Pin restricts a pointee through a projection/drop
  contract; deleting a C++ move constructor is not an equivalent proof for every accessor.
- Translate shared ownership separately from writable access. C++ mutable/shared_ptr does not provide
  RefCell-like live-borrow checks or Arc's payload trait guarantees.
- Preserve foreign ownership, allocator, nullability, and ABI contracts; a C++ pointer wrapper is not a Rust
  owner.
- Translate text by its contract: Rust str is valid UTF-8, C++ string stores arbitrary bytes; neither byte
  length nor Rust chars implements grapheme-aware UI behavior.
- Specify integer overflow, shifts, narrowing, NaN/order, and uninitialized storage instead of relying on
  C++ signed-overflow or default-construction assumptions.
- Translate template/structural constraints into Rust's nominal traits and coherence/orphan restrictions.
  Put foreign-type implementations behind an owned newtype when necessary; do not assume blanket impl freedom.
- Choose consuming methods and Fn/FnMut/FnOnce from capture/use semantics, not C++ callable spelling.
- Preserve Result/Option/exhaustiveness and unknown-variant policy rather than silently dropping error paths.
- Distinguish Rust const evaluation from C++ constexpr; check exact permitted operations and MSRV.
- Review macro expression evaluation, paths, generated unsafe, and external callers; hygiene is not a full
  proof.
- Translate lazy Rust futures separately from eagerly launched std::async work. Preserve pool, affinity,
  handle-drop, task supervision, cancellation, lock, and error policies across runtime boundaries.
- Keep intentionally rejected Rust examples labeled compile_fail; never run C++ undefined behavior as a test.
  Use the existing contract fixtures or focused paired programs only where they clarify a material difference.
