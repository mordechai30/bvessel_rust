# Project instructions

- Prefer explicit validation and straightforward control flow over shorter idioms. Accept extra complexity
  only for a material requirement or measured benefit; reject lint rewrites that obscure those decisions.
- Prefer suitable safe APIs. Permit necessary sound FFI and narrow reviewed unsafe abstractions when safe
  alternatives materially complicate code or dependencies. Do not reject a dependency for internal unsafe.
- Use the `rust` skill for Rust contracts, concurrency, unsafe boundaries, migration, and CPU performance.
- Use the `wgpu` skill for WebGPU through Rust wgpu/WGSL; use both skills for mixed host/shader work.
- Apply the project's rustfmt/style edition. For default formatting, use the Style Guide's
  [indentation and width][width], [comment width][comments], and [doc-comment placement][docs].

[width]: https://doc.rust-lang.org/style-guide/#indentation-and-line-width
[comments]: https://doc.rust-lang.org/style-guide/#comments
[docs]: https://doc.rust-lang.org/style-guide/#doc-comments
